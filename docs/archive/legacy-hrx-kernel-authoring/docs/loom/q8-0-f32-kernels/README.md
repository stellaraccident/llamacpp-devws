# Q8_0/F32 Kernel Sources

These are the concrete sources used in the gfx1100 Q8_0/F32 refutation and
Loom matching attempts. They were copied verbatim from `cache/hrx2` so the
kernel evidence is durable and reviewable without rerunning the generators.

Timing correction: the source/assembly evidence here remains valid, but the
final performance conclusion is superseded by
`../q8-0-f32-delta-root-cause-gfx1100.md`. A later common HIP module runner
loaded the Loom target ELF directly and measured the WG128 Loom artifact at p50
2.04 us versus HIP WG128 p50 2.00 us under `rocprofv3`.

## HIP Reference

- `hip_refute_q8_0_f32_rows_wg.hip.cpp`

  Generated by `tools/hrx2_q8_0_f32_refute.py` for run
  `gfx1100-q8-0-f32-refute-exact-20260612`.

  The focused reference routes are `--kernel=rows1_wg64` and
  `--kernel=rows1_wg128` with `--k=512 --rows=64 --cols=8`. Device timing from
  `rocprofv3 --kernel-trace` on the rerun was:

  - rows1/WG64: p50 1.88 us, mean 1.91 us over 1100 calls.
  - rows1/WG128: p50 2.00 us, mean 2.40 us over 1100 calls.

## Loom High-Level Attempts

- `loom_scalar_k512_r64_c8_rpg1_wg64.loom`

  Initial scalar schedule. Correct but says one quant per lane iteration, so
  the emitted schedule used scalar Q/RHS/scale work. Device time was about
  4.44 us.

- `loom_block4_k512_r64_c8_rpg1_wg64.loom`

  First useful WYSIWYG schedule: one lane owns four Q values within a Q8_0
  block and amortizes one scale over those values. Device time was about
  3.44 us.

- `loom_word4_rhsvec_dotf_k512_r64_c8_rpg1_wg64.loom`

  Forces packed Q payload load with `view<1xi32>`, RHS `vector<4xf32>` load,
  and `vector.dotf`. The target listing has `global_load_b32` for Q and
  `global_load_b128` for RHS. Device time from the profiled bundle was about
  3.36 us.

- `loom_word4_bitunpack_rhsvec_dotf_k512_r64_c8_rpg1_wg64.loom`

  Historical best high-level Loom source before the latest rerun. Uses
  `vector.bitunpacks<8>` on the packed Q word before F32 conversion, RHS vector
  load, and dot accumulation. Current generated WG128 variants from
  `tools/hrx2_q8_0_f32_tune.py` emit `global_load_b32`,
  `global_load_d16_b16`, `global_load_b128`, `v_bfe_i32`, `v_fma_mix_f32`, and
  `v_fmac_f32`. Loom/IREE dispatch-event profiling measured about 3.24-3.32 us
  for WG128 and 3.44 us for WG32/WG64, but the later common HIP module runner
  measured the same WG128 code object around p50 2.04 us. Treat the common
  runner as the decisive performance evidence.

- `loom_word4_bitunpack_unrolled_rhsvec_dotf_k512_r64_c8_rpg1_wg64.loom`

  Accepted focused WG64 parity source for `k=512`, `rows=64`, `cols=8`,
  `rows_per_workgroup=1`, `cols_per_group=1`, `WG64`. It exactly unrolls the
  two Q8 block iterations implied by `blocks_per_row=16` and `WG/8=8`, keeping
  the same packed Q word load, `vector.bitunpacks<8>`, RHS `vector<4xf32>`
  load, and `vector.dotf` accumulation. Same-runner `rocprofv3` device-time
  evidence measured Loom p50 at 1.96, 1.96, and 1.84 us versus HIP WG64 p50 at
  1.96, 1.96, and 1.96 us in three independent captures.

  Do not generalize this as "always fully unroll Q8": the same axis improved
  but did not close larger `4096x128x8` and `8192x128x8` evidence. Treat loop
  form and unroll factor as shape/target tuning axes.

- `loom_word4_bitunpack_scfunroll_rhsvec_dotf_k512_r64_c8_rpg1_wg64.loom`

  Preferred spelling of the same focused WG64 parity source. It preserves the
  Q8 block iteration as an `scf.for` with `unroll(%q8_unroll_factor)` instead
  of manually duplicating the loop body. The current unroll pass needs a
  statically provable trip count, so the source uses an ordinal loop
  `[0 to trip_count step 1]` and derives `block_idx = block_slot + ordinal *
  block_step` inside the body. With `trip_count=2` and
  `config.def @hrx2.tuning.q8_0_f32.unroll_factor = 2`, the emitted listing has
  no residual loop and the same broad instruction shape as the manual unrolled
  file.

  Same-runner `rocprofv3` device-time evidence measured Loom p50 at 1.96,
  1.96, and 1.96 us versus HIP WG64 p50 at 1.96, 1.96, and 1.96 us in three
  independent captures. Use this source as the Q8 high-level authoring
  exemplar; keep the manual-unrolled source only as a historical control.

- generated subgroup-reduce variant

  `tools/hrx2_q8_0_f32_tune.py` can generate
  `word4_bitunpack_rhsvec_dotf_subgroup`, constrained to WG32. It replaces
  `kernel.workgroup.reduce<addf>` with `kernel.subgroup.reduce<addf>` and
  passed correctness, but did not improve the focused Q8 shape.

## Low ASM Probes

- `loom_min_low_kernel_smoke.loom`

  Pure `low.kernel.def` smoke that compiles/runs through the low prep pipeline
  and writes `1.0` to an F32 output binding.

- `loom_low_isa_probe_bfe.loom`

  Historical attempt to spell `v_bfe_i32` in `asm<amdgpu.rdna3.core>`.
  The latest high-level `vector.bitunpacks<8>` path now emits `v_bfe_i32`, so
  this is no longer the primary Q8 blocker.

- `loom_low_isa_probe_fma_mix.loom`

  Historical attempt to spell `v_fma_mix_f32` in `asm<amdgpu.rdna3.core>`.
  The latest high-level path now emits `v_fma_mix_f32`, so this is no longer
  the primary Q8 blocker.

- `loom_low_isa_probe_d16_load.loom`

  Attempt to spell `global_load_d16_b16_saddr` in `asm<amdgpu.rdna3.core>`.
  Current result: parse failure, `unknown low asm mnemonic`.
